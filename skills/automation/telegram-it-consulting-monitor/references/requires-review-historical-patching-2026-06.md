# Historical requires-review cleanup — 2026-06

Задача: пользователь попросил не ограничиваться окном 7 дней, а взять вообще все сообщения, которые падали в `требует уточнения`, распределить по существующему словарю и сразу сделать production-патч.

## Что сработало

1. Не опираться на один analytics JSON.
   - `requires_review_posts` в analytics-артефактах может быть усечённым списком.
   - Для полного исторического прохода нужно переобходить все доступные `raw_logs/*_summary_input.json` через `build_digest_payload(...)`.

2. Разделить исправление на два слоя.
   - Слой 1: расширить общие rule-based паттерны для повторяющихся semantic классов.
   - Слой 2: для остаточного исторического хвоста добавить точечные override по `original_url`, если обобщение правила было бы слишком грубым.

3. После патча проверять не частично, а полным rebuild.
   - `python -m py_compile telegram_monitor_pipeline.py`
   - затем полный переобход всех `*_summary_input.json`
   - целевой критерий: `требует уточнения = 0` или явно выделенный небольшой спорный residue

## Какие паттерны потребовали расширения правил

Повторяющиеся классы, которые раньше часто падали в ambiguous:
- мероприятия: подкасты, конкурсы, прием заявок, регистрационные/сессионные форматы
- партнерства: статус business partner, соглашения, долевые сделки
- продукт/решение: демо, test-drive, on-premise, platform/gateway/generator device launch
- корпоративная новость: назначения, банкротства, увольнения, включение в перечни, статусные новости, поздравления
- обзор рынка: регуляторика, стандарты, правила, отраслевые новости, security-policy и legislative change posts
- аналитика: рыночные интерпретации, барьеры/пути роста, рациональность покупателей, смысловые обзоры без formal research artifact
- вакансии: стажировки, офферы, рекрутер, тестовое задание

## Когда нужен manual override

Использовать override по `original_url`, если одновременно верны условия:
- пост исторический и уже многократно всплывал в residue;
- смысл понятен человеку, но для общего regex/keyword-правила пришлось бы делать слишком широкий и опасный паттерн;
- пользователь просит «сразу патч», а не отдельный список на ручную валидацию.

## Зафиксированный результат сессии

- до патча historical residue: 74 сообщения
- после rule expansion + manual overrides: 0 сообщений типа `требует уточнения` по всем доступным `*_summary_input.json`

## Важная методологическая граница

Не «натягивать сову на глобус»:
- если пост действительно некуда уверенно отнести, лучше оставить маленький явно спорный residue;
- но если пользователь просит production cleanup и residue состоит из повторяющихся понятных классов, нужно не только составить список, а довести pipeline-патч до реально работающего состояния и проверить его full rebuild'ом.
