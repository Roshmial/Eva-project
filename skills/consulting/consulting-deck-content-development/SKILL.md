# Consulting deck content development

## Workflow

1. Establish the canonical artifact. If the user declares a Markdown brief the base, edit and agree that file first; do not change Gamma or another visual deck until explicitly asked.
2. Classify every slide before writing: executive summary, role value, mechanism, case, operating cycle, scaling, delivery, governance, or commercial close. Remove slides that only repeat the next slides.
3. Write conclusion-led titles that state the decision, benefit, or outcome. Avoid process labels and constructions of the form “не X, а Y”; state the positive conclusion directly.
4. Keep one offer name throughout. Describe embedded calculation methods as part of the offer instead of creating a second product by wording.
5. Normalize evidence slides to “Ситуация → Что сделали → Что получили”. Separate generic operating scenarios from concrete measured cases, and retain both only when their evidence level differs clearly.
6. Preserve claim status exactly: historical, calculated, potential, and realized effects are different claims. Upgrade a result to realized only when the user explicitly supplies that evidence.
7. Separate pilot depth from full-model depth. Define pilot outputs as concrete model artifacts and calculations; define full-model outputs as deeper logic and operating capabilities. Avoid presenting pilot work as “confirming potential” when the intended result is current-cost assessment.
8. Validate taxonomy layers before writing scaling slides. Keep cost pools, resources, solutions, and consumers separate; label commercial scopes that cross standard taxonomy objects as offering-specific constructs.
9. Generate the visual deck only from the approved source. Split one source slide into one visual card, remove production metadata and speaker notes from visible content, and derive the expected card count from the source.
10. Export and verify slide count, aspect ratio, placement of key facts, unchanged appendices, and prohibited content. Structural/text checks do not substitute for a visual review.

## User-facing content rules

- Give each executive role several distinct benefits; keep diagnostic questions in speaker notes.
- Use mechanism slides to explain how information becomes a decision, and case slides to prove what happened.
- Keep a single headline value range and prevent historical percentages from looking like additive promises.
- Show scalability through peer solution groups rather than a mixed list of technologies, spend classes, and organizational domains.
