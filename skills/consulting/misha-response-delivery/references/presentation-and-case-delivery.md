# Presentation and case delivery for Misha

Use this when the user asks for slide text, shortlist text, case blocks, or client-facing summaries.

## Delivery rules

- Prefer short factual phrasing over meta-commentary.
- Do not add caveat filler such as "информации немного", "лучше делить на", "публичных кейсов мало" inside the main presentation text unless the user explicitly asks for limitations.
- If data is incomplete, include only the facts that are actually available and stop there.
- When the user asks for a compact format like "номер кейса / компания / краткое описание", output exactly that structure without side commentary.
- Do not inflate a shortlist into a "full list" unless completeness was actually verified.
- For product shortlists, separate vendor, product, and adjacent systems cleanly so the slide does not mix a platform, a module, and a broad HR contour as if they were the same thing.

## Reference-driven SAP-style sales deck recipe

Use this sequence when an existing deck is named as the format reference:

1. Extract the reference structure and tone before writing. Reuse its sales logic, not its domain vocabulary.
2. Write the new content contract in one line: topic; current situation; target roles; target concept; use cases; evidence; automation components; next decision.
3. Default slide sequence:
   - conclusion-led title;
   - executive summary with context, management task, solution, potential, conditions, and requested decision;
   - value by the exact roles named by the user;
   - current-state gap and consequences;
   - target concept and calculation/data flow;
   - 3–4 use cases, each using situation → what changes → decision → potential effect;
   - effects and evidence status;
   - enabling systems and integrations;
   - bounded pilot and next decision.
4. Keep titles as conclusions. Keep slide bodies short enough to become visual cards, flows, or role columns rather than prose pages.
5. For effects, use a fixed evidence vocabulary:
   - `current fact supplied by client`;
   - `synthetic illustration from the model`;
   - `external benchmark / association`;
   - `reported result in an external case`;
   - `pilot hypothesis to validate`.
6. For automation slides, assign a job to every component. A credible project-economics contour normally separates CRM/sales, PSA/PPM projects-resources-timesheets, HR availability, ERP/payroll actual cost, catalog/norms, integration/history, calculation, and BI.
7. Run a terminology-leak scan before delivery: search for names and concepts unique to the reference deck and remove any that do not belong to the new topic.

## Common pitfalls

- Importing the reference deck's subject terminology when only its format and sales logic were requested.
- Saying that information is limited instead of simply writing the available facts.
- Expanding a one-slide request into a multi-slide structure.
- Mixing core HR/performance systems with adjacent task/project systems without a label.
- Collapsing a vendor and its specific product into one item when the distinction matters for a shortlist.
- Treating market benchmark differences as promised effects; preserve attribution and label them as external associations.
