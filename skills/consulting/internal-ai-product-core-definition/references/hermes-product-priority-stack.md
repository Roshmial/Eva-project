# Hermes product priority stack for internal-company positioning

Use this reference when defining Product Core or roadmap for Hermes in an environment where a generic corporate LLM chat already exists.

## Agreed priority order

1. Recurring scenarios / cron / monitoring / operational workflows
2. Chat-assistant for information gathering, calculations/models, and table generation
3. File processing and file generation
4. Dashboards

## Strategic implication

Do not position Hermes as 'another general AI chat'.
Position it as an internal AI product for:
- recurring execution;
- monitoring;
- files and artifacts;
- operational handoff.

## Future layer

Workflow layer is important, but should be built after the core is stable.
It should connect:
- chat;
- jobs;
- files;
- artifacts;
- handoff.

## Mandatory applied domains

The product core must explicitly account for these business-useful paths:
- commercial proposals (КП);
- requirements / business analysis / development docs / possible code path (ТЗ);
- email and internal systems.

## Practical framing

When reviewing roadmap readiness, separate:
- already usable now;
- ready for pilot / semi-manual rollout;
- not yet mature.

Do not confuse a capability with a product path.
