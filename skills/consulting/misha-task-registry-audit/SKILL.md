# Misha Task Registry Audit

## Когда использовать

Используй навык, когда Misha просит:
- поднять прошлые задачи;
- восстановить, на чём остановились;
- проверить, что уже решено и что ещё открыто;
- сверить наличие skills/tools под его персональную систему;
- не ходить по кругу по уже согласованным решениям.

## Источники по приоритету

1. `D:/LLM/hermes-logs/decision-log.md` — главный источник согласованных решений.
2. `session_search` — восстановление задач и контекста, которых ещё нет в decision-log.
3. `skills_list` и `skill_view` — проверка процедурной памяти.
4. `search_files/read_file` по рабочим папкам, если задача была связана с файлами.
5. Память пользователя — только для устойчивых предпочтений и правил, не для временных задач.

## Процедура

1. Сначала загрузи `decision-logging` и прочитай `D:/LLM/hermes-logs/decision-log.md`.
2. Составь список тем:
   - зафиксированные решения;
   - активные задачи;
   - открытые вопросы;
   - отклонённые варианты.
3. Проверь сессии по ключевым словам темы. Для блока `soul` искать минимум:
   - `soul`, `Soul`, `SOUL`, `душа`, `личностное развитие`, `саморазвитие`, `цели`, `ценности`, `энергия`, `обучение`.
4. Проверь skills:
   - карьерные;
   - рабочие/ИТ;
   - финансы;
   - саморазвитие;
   - Hermes/automation;
   - note-taking/decision logging.
5. Проверь tools через `hermes tools list`, если вопрос касается доступности инструментов.
6. Tools не включать и не менять без отдельного согласования с Misha. Разделять:
   - уже доступно;
   - желательно обсудить;
   - не нужно сейчас.
7. Если найден пробел в skills, можно создать или обновить skill самостоятельно, если пользователь явно разрешил это в задаче.
8. По итогам добавить компактную запись в decision-log, если появились новые устойчивые выводы.

## Формат результата для Misha

1. Краткий вывод.
2. Что поднято из источников.
3. Реестр задач по группам:
   - карьера/резюме;
   - автоматизация/Hermes;
   - рабочие ИТ/архитектура;
   - финансы;
   - личностное развитие / soul;
   - открытые вопросы.
4. Skills:
   - что уже есть;
   - что добавлено/исправлено;
   - что требует проверки.
5. Tools:
   - уже доступны;
   - кандидаты для отдельного обсуждения;
   - почему не подключать всё сразу.
6. Следующий конкретный шаг.

## Антипаттерны

- Начинать полный разбор заново, игнорируя decision-log.
- Делать вид, что `soul` найден, если поиск не дал фактов.
- Предлагать платные SaaS или внешние API без явной необходимости.
- Добавлять tools без согласования.
- Записывать в память временные номера задач, PR, cron-состояния или одноразовые факты.
