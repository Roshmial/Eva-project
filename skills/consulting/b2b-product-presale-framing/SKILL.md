# Purpose

Use this skill when the user asks how to package, position, or sell a technical product through diagnosis, discovery, or a broader client conversation.

Typical cases:
- move from a narrow deployment sale to a broader implementation project;
- build a presale path that reveals client need before product pitching;
- define what materials, questions, and steps are needed to qualify and expand a deal;
- separate a consulting-style entry layer from product delivery without pretending the company is selling classic standalone consulting.

# Core distinction

Always distinguish three different things explicitly:

1. standalone consulting service;
2. presale / qualification / discovery methodology;
3. product packaging and sale through a consulting layer.

Default interpretation for this user:
- if the topic is how to get from a request for deployment to a broader project, treat it first as a presale and deal-development problem;
- do not relabel presale mechanics as `consulting` too early;
- if the user objects that this is not consulting, accept that correction and move the framing upward into sales approach / presale methodology.

# Recommended answer structure

When the user asks for the selling logic, prefer an operational structure over abstract stages.

Best default format:
- step name;
- what we do;
- what we get;
- where payment begins.

Use clear Russian step names such as:
- `первое касание`
- `квалификация`
- `диагностика потребности`
- `формирование целевой модели`
- `платное обследование`
- `проектирование решения`
- `комплексное внедрение`
- `поддержка и развитие`

If the user asks for `по шагам, а не по этапам`, answer with an operational commercial path, not a maturity model or lifecycle taxonomy.

# Language rules

For this user and this class of task:
- avoid unnecessary English where there is a normal Russian equivalent;
- prefer `пресейл`, `квалификация`, `следующий коммерческий шаг`, `контур`, `каркас`, `вход в клиента`, `развитие сделки` over raw English like `framework`, `next step`, `engagement`, `scope`, `go-to-market` unless the English term is truly needed;
- keep the answer in natural business Russian, not mixed Russian-English jargon.

# What to avoid

- Do not confuse `подход к продаже` with `консалтинг как отдельная услуга`.
- Do not answer with product features rewritten as client problems.
- Do not stay at the level of generic stages when the user wants sales mechanics.
- Do not drift into a service catalog when the user is asking for a deal path.
- Do not overuse English business labels when the user explicitly asks for more Russian.

# Good reframing pattern

If the user says something like:
- `это не консалтинг, это подход к упаковке продукта через слой консалтинга`

then align immediately and use wording like:
- `это не консалтинг как услуга, а сценарий пресейла и квалификации клиента`;
- `это продажа продукта через консалтинговую рамку`;
- `это инструмент продажи и развития сделки`.

# Verification

Before finalizing, check:
- did you clearly separate consulting service vs presale methodology vs product packaging;
- did you answer in operational steps when the user asked for steps;
- did you use normal Russian labels instead of avoidable English;
- did you show where the free part ends and where paid work begins.
