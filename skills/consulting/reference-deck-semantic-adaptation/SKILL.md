# Adapt an approved reference deck

For Misha, an approved presentation reference fixes the semantic and visual contract of EVERY slide, not merely its theme or topic order.

- Inventory each slide before editing: function, block count, KPI count, diagram type, image placement, hierarchy, and composition. Build an explicit reference-element → replacement-content mapping.
- Preserve these counts and functions exactly. In the RSM-to-business-case adaptation, slide 2 specifically requires FOUR content blocks and TWO KPIs. Do not replace them with three columns or a process diagram.
- Preserve slide order, card counts, summary/detail relationships, and visual emphasis throughout. Fit relevant service content into the existing structure; shorten wording rather than silently redesigning it. Keep “current offer scope” and “expansion potential” semantically distinct: roadmap and implementation components remain inside the current strategy offer; expansion names adjacent strategies or service families such as AI, data, business applications, cybersecurity, workplace, or IT operating model.
- Case-slide result fields must state what the client receives from the service. A case must remain a client decision situation, not a renamed service component: portfolio analysis, target architecture, roadmap, and governance model are strategy artifacts, while business growth, data-center renewal, regulatory constraints, and cloud-model choice are valid strategic cases. Investment-case calculation must not promise strategy development, architecture design, or migration planning when these are separate services or inputs.
- Preserve the title composition: generated abstract visual on the left, compact title/subtitle on the right. An image is part of the design contract; a process diagram or generic icon is not a substitute. If generating a new image, keep the approved artistic language and crop.
- Never invent KPI values to fill the required KPI slots. Match each KPI to the offer stage: a strategy deck uses measures of strategic alignment, maturity, decision quality, or goal attainment; migration savings and implementation speed belong to delivery. Use sourced appropriate values or clearly defined calculation metrics, with status and units explicit. When a case needs a number, label an external benchmark as research context rather than achieved client impact.
- Gamma template generation is a regeneration, NOT deterministic layout preservation. It can change card composition, shrink text, drop matrices, and alter block counts despite instructions. Do not repeatedly regenerate and call the result a faithful adaptation.
- An updated PPTX does not complete a Gamma deliverable. Deliver and verify the actual new/updated Gamma URL. If editor/import access is blocked, report the unmet requirement explicitly.
- Verify three independent dimensions: semantic element mapping, content accuracy, and rendered visual correspondence. Slide count, XML geometry, or absence of out-of-bounds text alone cannot establish acceptance. Compare full-size renders against the reference slide by slide.
- Do not say layout, typography, or visual identity is preserved unless actual rendered comparison supports it. Contact sheets only reveal broad problems; inspect dense slides full-size.
