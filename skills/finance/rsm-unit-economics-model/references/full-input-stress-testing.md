# Полное заполнение и стресс-проверка РСМ-модели

## Назначение

Используй этот чек-лист после сборки или существенной правки проектно-ресурсной модели. Цель — проявить ошибки, которые не видны в пустом шаблоне: циклы диапазонов, двойной учёт пула, смешение потребности и наличия, некорректный нулевой EAC и несовместимость пустых критериев.

## Подготовка тестовой копии

1. Сохрани чистый шаблон и создай одну отдельную копию с явной маркировкой «синтетические данные».
2. Заполни все разблокированные пользовательские ячейки. Проверь программно, что `blank unlocked cells = 0`.
3. Используй максимальную предусмотренную ёмкость регистров, а не несколько демонстрационных строк.
4. Обеспечь полный охват каталога, месяцев, направлений, размеров и типов ресурсов.
5. Для числовых полей ставь явный `0`, если сценарий означает отсутствие объёма или ручного override.
6. Смешай режимы: часть проектных затрат вводится вручную, часть рассчитывается из полного пула; часть проектов завершена, часть имеет прогноз остатка; обычные и беззатратные продукты присутствуют одновременно.

## Независимый пересчёт

Рассчитай вне Excel из входных данных:

- плановую потребность по `продажи × норматив × профиль`;
- требуемый headcount по потребности;
- полный оплачиваемый пул по максимуму требуемой и доступной мощности;
- ручную месячную часть проектных затрат;
- остаток пула для неручных строк;
- нераспределённый пул;
- фактические прямые затраты проекта;
- `EAC = факт прямых затрат + прогноз остатка + прочие будущие прямые затраты`;
- признанную выручку с ограничением суммой договора;
- P&L проектов, направлений и компании.

Обязательные тождества с денежной погрешностью не выше выбранного машинного допуска:

- `ручные + распределённые неручные + нераспределённые = полный ресурсный пул`;
- `EAC = факт + остаток`;
- `сумма проектов = направление`;
- `сумма направлений = компания`;
- `прибыль = признанная выручка − прямые затраты − нераспределённый пул − накладные`;
- `накопленная признанная выручка ≤ сумма договора`.

## Компактные формульные сценарии

1. Один проект, одна человеческая роль, два месяца потребления: проверь часы, округление до сотрудника, полный пул, проектные затраты, EAC, выручку и маржу.
2. Два проекта делят один ресурс: задай известный полный пул и проверь пропорциональное распределение и нулевой остаток.
3. Ручная часть плюс автоматическая часть: проверь, что автоматическая аллокация использует только остаток после ручных сумм.
4. Нулевой EAC: обычный проект признаёт ноль и попадает в контроль; продукт с явным правилом «в момент продажи» признаёт договор в месяце сделки.

## Технические ворота

- уникальные `Project_ID` и ключи `Project_ID × Resource_ID`;
- валидные `Product_ID` и `Resource_ID`;
- профили нормативов суммарно 100%;
- дискретные ресурсы целочисленны;
- отсутствуют `#REF!`, внешние связи, structured references и формулы по целым столбцам;
- все диапазоны одного `SUMIFS` одинакового размера;
- длина каждой формулы меньше 8192 символов;
- ZIP/XML проходит проверку;
- чистый шаблон и заполненная копия повторно читаются после сохранения.

Если полный сторонний Excel-движок не справляется с большой книгой, не объявляй расчёт подтверждённым по структурной проверке. Используй независимый пересчёт всех экономических тождеств плюс компактные формульные сценарии и явно укажи отсутствие визуальной проверки в настольном Excel.
