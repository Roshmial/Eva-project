# UI 8.5+ polish loop for Hermes Web React

Когда functional parity уже есть, а пользователь требует честный product-level `8.5+`, полезен короткий повторяемый цикл:

1. Снять baseline-оценку по ключевым экранам через `browser_vision`.
   - В этой сессии получилось примерно так:
     - chat: ~5.5 → 7.3 → 7.8 → 8.1 → 8.3/8.4
     - jobs/admin/profile: около 6.5–6.7 до первого сильного pass

2. Не распыляться на всё приложение, если один экран тянет вниз общий уровень.
   - Здесь таким экраном был `chat`.

3. Самый быстрый ROI-порядок для chat-first polish:
   - прояснить composer semantics (`Сообщение в чат` / `Поставьте задачу Hermes` / `Отправить в Hermes`);
   - сделать пошаговый funnel `описать → добавить контекст → отправить`;
   - убрать шум bulk-контекста под disclosure;
   - сузить правую панель и вернуть вес центру;
   - de-boxing левого списка чатов + более жёсткий truncation;
   - добавить low-activity hint, если в центре пока 0–1 сообщение.

4. Не закрывать задачу по инерции после parity-pass.
   - Если пользователь явно говорит `доводим UI до 8.5+`, старый статус `completed` по parity нельзя считать достаточным.
   - Нужен новый live verdict по текущему экрану.

5. Честный стоп-критерий.
   - Если live-оценка ещё ниже 8.5, нужно зафиксировать не «почти готово», а конкретные остатки.
   - В этой сессии главные остатки после 8.1 были:
     - пустоватая центральная рабочая зона;
     - правая панель всё ещё ощущается отдельным сайдблоком, а не органичной частью chat-flow.

6. Полезная формулировка для финального статуса:
   - не «готово», а «сейчас это скорее 8.3–8.4, уже ближе к 8.5, чем к 8.2; остаются 2 главные причины ...»
