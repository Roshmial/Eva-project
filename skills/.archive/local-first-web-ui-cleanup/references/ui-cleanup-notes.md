# UI cleanup notes for Hermes Web MVP

Короткий session-specific конспект того, что сработало на этом проходе.

## Что оказалось критичным

- Светлая тема сразу уменьшила ощущение перегруза сильнее, чем точечные правки spacing.
- Самая болезненная UX-проблема была не в цветах, а в дублях смысла: профиль и настройки ответа жили в нескольких местах одновременно.
- Для admin user form нужно было развести DOM id режима формы и DOM id personalization mode; конфликт id — это не косметика, а реальный runtime-риск.

## Полезные приёмы

- Проверять не только тексты и стили, но и остатки старых JS handlers после удаления modal/secondary flow.
- После cleanup прогонять поиск по старым именам (`styleModal`, `openStyleModal`, и т.п.), чтобы не оставить мёртвые ссылки.
- Проверять duplicate ids простым HTML-парсингом — это дешёвый и полезный sanity check.
- После UI cleanup повторно пройтись по UX/UI best practices, а не останавливаться на синтаксисе.

## Что ещё обычно остаётся тяжёлым после первого pass

- admin screen
- job detail screen
- composer с вторичными действиями рядом с отправкой

## Что проверять в следующий раз

- нет ли повторной загрузки `config.js`
- не остались ли техничные формулировки уровня `raw cron`, `source of truth`, `workspace` внутри русской фразы
- не пытается ли browser-based приёмка открыть `about:blank` вместо реальной локальной страницы; если так, подтверждать состояние через live HTTP, структуру HTML/JS и runtime checks
