# Hermes Web UI: пользовательские предпочтения и проверенные UX-правки

Когда пользователь просит «допилить UI» в local-first web MVP, сначала проверь не только отдельные компоненты, но и информационную архитектуру shell.

Что оказалось устойчиво полезным:
- Верхнюю навигацию лучше выносить в topbar как вкладки, а не держать отдельным тяжёлым блоком в sidebar.
- Профиль и выход лучше привязывать к статусной зоне «готово к работе», чтобы это выглядело как часть операционного контекста, а не отдельный шумный раздел.
- Для кнопок со служебными действиями в sidebar лучше сразу закладывать двухстрочный текст и одинаковую высоту, чтобы они не «ломались» от переноса.
- Для пользовательских сообщений на синем фоне нужно отдельно проверять контраст времени/метаданных; серый по умолчанию может стать нечитаемым.
- Историю чатов стоит ужимать: не дублировать title и preview, а использовать компактный заголовок. Если title дефолтный, лучше брать первую осмысленную фразу пользователя.
- Для текстового ввода в чатах по умолчанию удобнее: Enter — отправить, Shift+Enter — новая строка.
- В интерфейсе на русском пользователь может явно отвергать разговорные ярлыки вроде «Админка»; безопаснее выбирать деловые подписи уровня «Управление».
- После текстовых cleanup-правок profile summary надо перепроверять живым smoke, потому что старые фразы могут оставаться в рендере, даже если они уже убраны из основной разметки.

Практика верификации после UI-пакета:
1. Синтаксис frontend/backend.
2. Быстрый triage на доступность frontend/backend/auth/bootstrap.
3. Полный browser acceptance smoke по chat/profile/admin/jobs.
4. Если smoke подсветил старый текст или регрессию, добить точечно и прогнать smoke повторно, а не считать задачу закрытой по коду.
