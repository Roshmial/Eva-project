# Split live contour discipline

## Когда читать
- У продукта раздельные live-контуры: UI на одном хосте, backend/API/DB — на другом.
- Пользователь явно назвал «главный live UI», и есть риск незаметно подменить проверку backend-контуром.

## Главное правило
Если пользовательский симптом относится к live UI, подтверждение исправления должно проходить на каноническом UI-хосте, который пользователь реально открывает.

Проверки на backend-хосте полезны только как вспомогательная диагностика. Они не доказывают, что user-facing проблема исправлена.

## Практика
1. В начале задачи зафиксируй отдельно:
   - канонический UI host/port;
   - backend/API host/port;
   - БД/служебный хост, если он отдельный.
2. В каждом промежуточном выводе явно помечай, на каком контуре получен факт.
3. Не говори «починено на live», если исправление проверено только на backend-контуре.
4. Если backend и UI разведены по разным узлам, сначала чинить можно где угодно, но финальная верификация — только на каноническом UI.
5. Если доступ к каноническому UI-хосту ограничен, честно зафиксируй blocker и не подменяй его smoke-проверкой соседнего узла.

## Симптомы, что ты ушёл не туда
- Backend/API уже зелёные, а пользователь всё ещё видит старое поведение.
- Собран новый frontend bundle, но не на том хосте, где живёт реальный UI.
- Проверка идёт через localhost/служебный порт, а пользователь открывает другой адрес.
- В отчёте смешаны формулировки вида «на 178 всё ок, значит 95 исправлен».

## Формулировка для отчёта
- «Backend fix готов и проверен на <backend-host>, но live UI пользователя находится на <ui-host>; без проверки там нельзя считать user-facing инцидент закрытым.»
- «Это не regression backend-path, а contour mismatch: я проверила не тот live surface.»

## Что дало ценность в этой сессии
- Пользователь явно поправил рабочую дисциплину: `95.182.85.233:8803` — основной live UI-контур Hermes Web, его нельзя подменять проверками/фиксами на `178`.
- Такой сигнал должен попадать не только в memory, но и в class-level skill для live UI/runtime verification.
