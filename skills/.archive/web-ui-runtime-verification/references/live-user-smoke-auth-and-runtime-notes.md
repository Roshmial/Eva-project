# Live user smoke: auth/runtime pitfalls

## Когда это читать
Когда server-side тесты зелёные, а повторная проверка именно через пользователя в UI всё ещё расходится с ожиданием.

## Полезные проверки

1. Сначала проверить, в какую БД реально смотрит живой backend.
   - Не предполагать DuckDB только потому, что локально есть `data/*.duckdb`.
   - Снять env у живого процесса и проверить `HERMES_WEB_BACKEND_DSN` / driver.
   - Если live contour сидит на Postgres, ручное создание smoke-user в DuckDB не поможет для UI login.

2. Разделять два вида проверки:
   - `app.test_client()` / локальный импорт backend-модуля;
   - живой `POST /api/auth/login` на runtime endpoint.
   Если первое зелёное, а второе нет, значит надо проверять не пароль как таковой, а live runtime contour: DSN, process env, restart, proxy path.

3. Не считать `runtime_env.sh <command>` исполняющим контрактом, пока это не подтверждено кодом.
   Для этого контура безопасный паттерн такой:
   - `source ../../scripts/runtime_env.sh && <command>`
   - либо явный запуск через shell с `source ...` и затем `exec <command>`.
   Иначе можно получить ложное ощущение, что команда запущена в правильном runtime env.

4. Для повторной проверки "через пользователя" фиксировать успех только если выполнена вся цепочка:
   - UI login успешен;
   - создан новый чат;
   - пользовательский запрос отправлен через composer;
   - сообщение вышло из `processing_status`;
   - в UI виден финальный assistant reply;
   - в backend у соответствующего `chat_task` статус `completed`.

5. Если первый user-run после рестарта завис в `processing_status`, не делать вывод сразу.
   Проверить `chat_tasks` в БД и повторить новый чат/новую задачу после стабилизации runtime. В этой сессии предыдущая задача завершилась позже, а следующий новый user-run уже прошёл нормально.

## Что именно оказалось полезным в этой сессии
- Реальный prod backend работал с `HERMES_WEB_BACKEND_DSN=postgresql:///hermes_web`, а не с локальным DuckDB-файлом.
- Поэтому smoke-user надо было создавать в live Postgres, иначе UI login закономерно возвращал `invalid_credentials`.
- После исправления subject extraction и нормального runtime restart сценарий через UI с запросом `Собери из интернета данные по рынку LegalAI и дай дашборд.` завершился успешно: пользовательский ответ пришёл в UI, а `chat_task` перешёл в `completed`.
