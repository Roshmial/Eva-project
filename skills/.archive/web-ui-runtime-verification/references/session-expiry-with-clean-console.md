# Session expiry can happen with a clean browser console

## Why this matters

Во время live acceptance UI может выглядеть "технически чистым":
- нет `js_errors` в browser console;
- сетевой/DOM путь в целом работает;
- backend health зелёный.

Но при этом пользовательский контур всё равно может деградировать через auth/session UX:
- всплывает `Сессия истекла. Войдите снова.`;
- форма чата ещё видна, но фактическая сессия уже сброшена;
- дальнейшие действия требуют повторного login.

## Durable lesson

Отсутствие console errors **не является** достаточным доказательством, что UI-session жива и acceptance закрыт.

## What to do in acceptance

1. Проверить не только console, но и верхнеуровневые user-signals:
   - есть ли баннер/текст про истечение сессии;
   - сохранилась ли возможность открыть/создать чат без повторного входа;
   - не перескочил ли UI обратно на login screen после обычного действия (`+ Новый чат`, переход между чатами, reload).
2. Если всплыло `Сессия истекла. Войдите снова.`:
   - не списывать это на браузерный шум;
   - зафиксировать как отдельный UX/runtime symptom;
   - повторно залогиниться и продолжить сценарий, но не закрывать acceptance как полностью чистый.
3. В итоговом статусе развести:
   - functional path работает / не работает;
   - session UX стабилен / нестабилен.

## Good final wording

- `Сценарий проходит, но есть отдельный UX-хвост: session expiry может всплывать без console errors.`
- `Console clean != session healthy; auth/session stability проверять отдельным user-path.`
