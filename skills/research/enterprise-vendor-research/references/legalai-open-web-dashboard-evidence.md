# LegalAI open-web dashboard evidence pattern

Use when the user asks for a client-facing LegalAI market dashboard and open-web access is partial.

## Situation pattern

- browser SERP is noisy, blocked, or visually incomplete;
- analyst market reports expose usable numbers only in search-result snippets;
- accessible public pages still exist for adoption surveys, press, and funding signals;
- the task requires a usable dashboard anyway, not a failed search report.

## Evidence hierarchy

1. Accessible first-hand pages:
   - vendor/product research pages;
   - named survey pages;
   - reputable press/news pages;
   - investor/funding coverage.
2. Search-result snippets from named analyst-report pages.
3. Secondary commentary only if it adds context and the primary page is inaccessible.

## Recommended dashboard composition

- Summary cards:
  - one cautious market-size range if multiple public estimates disagree;
  - one growth-rate range if available;
  - one adoption or funding signal.
- Sections:
  - what is directly supported;
  - demand/adoption signals;
  - capital/competition signals;
  - strategic implications;
  - evidence limitations.
- Sources:
  - list the named report landing pages and directly accessible survey/press pages.

## Wording discipline

Use phrases that preserve evidence boundaries:

- `открытая оценка рынка`;
- `по открытому сниппету поисковой выдачи`;
- `оценка из публично доступного описания отчёта`;
- `публичные данные расходятся`;
- `число стоит трактовать как ориентир, а не как точную базу для финансовой модели`.

Avoid flattening snippet-derived figures into unquestioned facts.

## LegalAI-specific signal mix that worked well

- market size / CAGR from named analyst-report snippets;
- adoption and usage posture from Thomson Reuters / LexisNexis survey pages;
- funding and ARR signal from Reuters coverage of Harvey;
- interpretation: the stronger signal is not exact TAM precision, but convergence of adoption, efficiency demand, and capital inflow.
