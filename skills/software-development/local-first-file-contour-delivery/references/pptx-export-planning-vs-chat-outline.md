# PPTX export: planning vs chat-outline

## Когда пригодится

Используй эту заметку, когда generated `pptx` уже технически открывается, но по качеству всё ещё выглядит как механически упакованный чатовый ответ.

## Наблюдавшийся паттерн

Старый deck может содержать сразу несколько классов дефекта:
- limitation/apology-прелюдия попадает на первые слайды;
- заголовки сохраняются как `Слайд N – ...` вместо нормальных названий разделов;
- в конце доезжает сервисный хвост вроде `Вы можете создать новую презентацию...`;
- секции режутся на мелкие куски по фиксированному числу строк, поэтому deck становится длинным, но не презентационным.

## Что улучшать в backend

1. Сначала санация body:
- отрезать prelude про невозможность создать бинарный файл;
- отрезать сервисные CTA-хвосты (`При необходимости я могу помочь...`, `Дайте знать...`).

2. Затем нормализация структуры:
- убирать `Слайд N –` / `Slide N -` из heading-ов;
- выделять `Заголовок` / `Подзаголовок` как label-ы для title slide;
- собирать `sections` отдельно от title metadata.

3. Затем planning слайдов:
- title slide из label-ов;
- overview slide со структурой разделов;
- label-only sections -> card/grid slide;
- narrative sections -> более крупные смысловые chunks, а не микрослайды.

## Как тестировать

Полезные проверки regression:
- в DOCX/PPTX не попала limitation-прелюдия;
- в DOCX/PPTX не попал сервисный хвост `Вы можете создать новую презентацию...`;
- PPTX содержит overview/structure slide;
- буквальные заголовки `Слайд N – ...` не торчат в user-facing тексте.

## Важное ограничение acceptance

Не считай roundtrip из уже экспортированного старого `.pptx` источником истины о качестве нового builder-а.

Почему:
- `.pptx` уже flatten-ит исходную markdown/section-структуру;
- внутри остаются legacy-текстовые артефакты, которые новый builder честно примет как вход;
- это полезно только как negative example / symptom reference.

Источники истины для новой логики:
- исходный generated text;
- targeted regression fixtures;
- builder-level tests.
