# Chat archive semantics + popover harmony

Короткий reference по polish-pass для chat-first local-first React UI.

## 1. Семантика архива в чатах

Если пользователь говорит, что `В архив` должно скрывать чат с основной страницы, это значит:
- sidebar и основной список активных чатов фильтруются по `!thread.archived`;
- архивный чат остаётся доступным в `Все чаты` или отдельном архивном представлении;
- label `Скрыть` не должен оставаться как ложная UX-модель, если backend живёт на `archived`;
- при архивировании текущего активного чата UI должен сразу уйти на следующий неархивный чат или безопасный fallback.

Практический smell:
- модалка `Все чаты` уже переключает `archived`, но sidebar продолжает брать `appState.threads` без фильтра и создаёт ложное ощущение, что архив `не работает`.

## 2. Desktop polish без поломки mobile

Если mobile уже принят пользователем, а доработка нужна для desktop/iPad:
- не делай широкую переделку mobile breakpoint-ов;
- сначала вводи общие CSS tokens: body/label/meta/title sizes, line-height, control height, panel padding, section/card gaps;
- потом подключай к ним общие surface-элементы: buttons, inputs, labels, cards, modal, section headers, table rows;
- только после этого лечи отдельные desktop-перекосы ширины (`Файлы` vs `Параметры`) через desktop-safe min/max width.

Это даёт более устойчивый результат, чем серия точечных `font-size`/`padding` фиксов по секциям.

## 3. Popover contract для `Файлы` / `Параметры`

Базовый visual contract:
- одинаковая типографическая шкала;
- одинаковый line-height;
- одинаковый размер кнопок и внутренних отступов;
- на desktop поповеры должны выглядеть как элементы одной системы, а не два разных виджета;
- длинные file names / descriptions обязаны переноситься, а action-кнопка не должна ломать layout карточки.

Минимальные CSS-признаки:
- `overflow-wrap: anywhere` / `word-break: break-word` для file-card текста;
- текстовая часть карточки файла должна жить в `min-width: 0; flex: 1 1 auto;`;
- desktop width для `Параметры` не держать в узком коридоре `168–220px`, если рядом `Файлы` уже явно шире;
- mobile overrides должны остаться отдельным слоем и не затираться desktop harmonization pass.

## 4. Acceptance after polish

После такого pass проверять не только build:
- какой чат открывается по умолчанию;
- исчезает ли архивный чат из sidebar сразу после архивации;
- остаётся ли он доступен через `Все чаты`;
- одинаково ли выглядят `Файлы`, `Параметры`, `Управление`, `Задачи`, `Профиль` по размеру шрифтов и ритму;
- не сломалась ли уже принятая mobile вёрстка.
