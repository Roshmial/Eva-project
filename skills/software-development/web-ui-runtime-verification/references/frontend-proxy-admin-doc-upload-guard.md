# Frontend proxy, admin runtime wiring, document extraction и post-guard

Когда использовать:
- split-contour Hermes Web, где frontend живёт на одном сервере/порту, а backend на другом;
- жалобы вида `frontend_proxy_upstream_unavailable`;
- админка видна, но конкретная вкладка падает уже после открытия;
- пользователи жалуются, что из загруженного документа распозналось не всё;
- в чат иногда уходит мусорный LLM-ответ или tool transcript вместо нормального текста.

## 1. Frontend proxy сначала проверяй как продуктовый маршрут, а не только по unit/env

Надёжный минимальный порядок:
1. Подтвердить фронтовый origin.
2. Спросить именно frontend `/api/service-info`, а не только backend напрямую.
3. Если frontend даёт `frontend_proxy_upstream_unavailable`, проверить фактический upstream (`HERMES_WEB_FRONTEND_BACKEND_BASE` или эквивалент) и сверить его с целевым backend-хостом.
4. После правки обязательно повторить запрос именно через frontend origin.

Практический инвариант для такого класса задач:
- `frontend origin /api/service-info = 200` важнее, чем просто `backend /api/service-info = 200`, потому что пользователь ломается именно на проксируемом продуктовым frontend-пути.

## 2. Для admin runtime defect не останавливайся на факте, что кнопка видна

Если пользователь говорит, что вкладка `Управление` не открывается:
- отдельно подтвердить, что кнопка есть в DOM и доступна роли/viewport;
- отдельно кликнуть и сразу проверить console/runtime errors;
- отдельно сверить точный JSX вызов screen-компонента в root render.

Durable pitfall:
- экран может падать не из-за прав или маршрутизации, а из-за drift имени handler-а в root render (`onSaveNotice={...}` указывает на несуществующую функцию, тогда как реальный handler назван иначе).
- Такой дефект не всегда ловится визуально до открытия экрана, а build может оставаться зелёным, если путь активируется только в runtime-конфигурации.

## 3. Для document extraction считай таблицы и служебные зоны first-class контентом

Если пользователь говорит `распозналось не всё` для ТЗ/брифа/спецификации:
- не ограничивайся `paragraphs` у DOCX;
- проверяй таблицы;
- проверяй header/footer;
- для XLSX делай текстовую проекцию по листам и строкам.

Практическая причина:
- многие ТЗ хранят структуру именно в таблицах, и простое извлечение `document.paragraphs` создаёт ложное ощущение, что OCR/распознавание `работает`, хотя теряется значимая часть документа.

## 4. Для жалоб на session timeout различай формулу и дефолт

Если сессия должна жить `1 час от последней активности`:
- сначала проверь, что expiry считается от `last_seen_at`, а не от `created_at`;
- отдельно проверь runtime/default TTL env.

Durable pitfall:
- формула может быть уже правильной, но дефолтный TTL слишком большой или слишком старый относительно продуктового ожидания. Тогда баг не в lifecycle-функции, а в дефолте/конфиге.

## 5. Для internet research правило `источники обязательны` вноси в backend/system prompt, а не только в UI copy

Если продуктовый дефект звучит как `нельзя тащить непроверенные данные`:
- этого недостаточно на уровне help-text или ожиданий пользователя;
- правило должно жить в системном prompt/backend policy: при ответах по интернету обязательны источники, непроверенные выводы нельзя выдавать как факт.

## 6. Для сбоев модели добавляй post-generation guard

Если в чат уходит `портянка`, tool transcript или явный технический мусор:
- проверяй ответ модели после генерации, до публикации пользователю;
- блокируй признаки tool transcript (`<tool_code>`, `write_file(`, `execute_code(` и т.п.);
- блокируй технические traceback-подобные ответы;
- при желании добавляй простой repetitive-text heuristic как cheap guard.

Это отдельный acceptance-layer: не только `модель ответила`, но и `ответ publishable`.

## 7. Что полезно сохранять как regression tests

Для такого класса задач high-ROI regression набор:
- frontend proxy через product origin;
- session TTL default и expiry от `last_seen_at`;
- DOCX extraction: body + table + header/footer;
- XLSX extraction по листам;
- post-guard на generic LLM garbage/tool transcript.
