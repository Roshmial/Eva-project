# Chat layout and second-pass contract sync

Когда полезно:
- второй или третий UI/UX-pass по уже живому local-first web MVP;
- пользователь даёт точный список дельт по чатам, jobs и админке;
- большие ванильные `index.html + app.js` уже правились адресными патчами.

Ключевые уроки:
1. Изменение «плашки должны быть постоянной частью вкладки Чаты, а не жить в ленте» — это IA-изменение экрана. Его надо проверять вместе с layout, scroll mode и поведением composer.
2. Если пользователь говорит, что отдельная кнопка вроде `Сделать cron из чата` не нужна, удаляй не только DOM-элемент, но и весь JS-path: `els`, listeners, helper-функции, secondary copy.
3. Для открытия чата и отправки сообщений полезен явный режим прокрутки `top / bottom / preserve`, а не одна жёсткая прокрутка на все случаи.
4. На втором проходе легко промахнуться мимо реального состояния файла. Безопасный порядок: перечитать текущий render-блок, затем sync DOM ids, затем sync JS handlers, затем sync backend payload и только после этого идти в smoke.
5. Если админка перестраивается с карточек на таблицы + detail-card, нужно синхронно обновлять:
   - HTML placeholders;
   - `els` map;
   - `render...()` функции;
   - click handlers (`data-*`);
   - backend shape для overview/list/detail.

Практический чек перед объявлением прогресса:
- новая разметка экрана уже есть;
- старые кнопки и их listeners действительно удалены;
- `render...()` не пытается писать в исчезнувшие DOM-узлы;
- backend отдаёт именно те поля, которые ждёт новый overview/list/detail;
- smoke проверяет пользовательскую дельту, а не только "страница открылась".
