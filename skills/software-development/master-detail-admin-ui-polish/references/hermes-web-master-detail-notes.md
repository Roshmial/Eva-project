# Hermes Web: заметки по master/detail-polish

Короткие практические выводы из живых проходов по Hermes Web MVP.

## 1. Что чаще всего делает экран тяжёлым
- длинная верхняя шапка + отдельный section-header + отдельный toolbar;
- много карточек с одинаковым визуальным весом;
- растянутый блок метаданных между hero и вторичными секциями;
- список слева как "карточки внутри карточки";
- повтор одного и того же статуса почти у всех элементов.

## 2. Что даёт быстрый эффект без перепридумывания экрана
- уменьшить gap/padding/radius у list/detail;
- сделать active-state заметным через inset-полоску или более явную подложку;
- сократить описательную шапку до одной рабочей фразы;
- превратить большой meta-block в compact mini-summary;
- сделать primary-action действительно primary.

## 3. Проверка после правок
Минимальный runtime-check:
- открыть целевой раздел;
- измерить основные блоки через DOM/console при необходимости;
- кликнуть не только default item, но и ещё один элемент списка;
- сравнить active item и detail title;
- проверить, что action-кнопки и secondary labels обновились вместе с detail;
- посмотреть console errors.

## 4. Что считать хорошим результатом
Не "идеальный редизайн", а:
- экран визуально спокойнее;
- главный сценарий читается быстрее;
- selected item и detail лучше связаны;
- критических поломок нет;
- пользователь перестаёт ощущать экран как сырой MVP.
