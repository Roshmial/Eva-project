# Chat surface acceptance checklist

Используй этот список для live-приёмки после правок во вкладке чатов.

## 1. Открытие и позиция

- Открой существующий длинный чат.
- Убедись, что при входе виден конец обсуждения, а не первые сообщения.
- Переключись между несколькими чатами и проверь, что позиция не залипает от предыдущего thread.

## 2. Scroll contour

- Проверь, какой именно контейнер скроллится.
- При длинной истории header/nav не должны неожиданно исчезать, если задумана sticky-схема.
- Composer должен либо быть закреплён, либо двигаться консистентно вместе с тем контейнером, который выбран главным scroll-контуром.

## 3. Composer и guide banner

- Проверь состояние с warning/banner.
- Проверь состояние без banner.
- Проверь empty/welcome state отдельно от обычного message list.

## 4. Вложения в сообщениях

- Отправь файл от пользователя.
- Убедись, что имя файла, ссылка и вторичный текст читаемы на фоне user bubble.
- Проверь hover/focus, если это ссылка.

## 5. Structured artifacts

Проверь минимум три сценария:

- обычный assistant message;
- clarification_request;
- approval_request или другой special artifact, если он поддерживается backend.

Для clarification message важно, чтобы были видны:

- title;
- prompt;
- options, если они переданы в meta.

## 6. Dashboard flow

- CTA/label не должны быть прибиты к одному домену, если инструмент заявлен как универсальный.
- Если источник данных неясен, UI должен показать уточнение, а не строить неверный частный сценарий молча.
- Если источник распознан, artifact должен рендериться как осознанный dashboard result.

## 7. Финальное подтверждение

Задача не считается завершённой, пока не пройдены:

- build;
- backend/API smoke;
- browser/live acceptance.
